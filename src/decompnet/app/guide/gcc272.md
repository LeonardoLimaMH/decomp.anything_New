# GCC 2.7.2 (PSY-Q) at -O2: which C gives which code

Levers for near misses in PlayStation code built with GCC 2.7.x/2.8.x and maspsx. Each is a hypothesis to test with
`compile_and_diff`, not a rule. Prefer order and lifetime levers before `register` pins. (Written for this project from
public knowledge of the compiler's passes; the facts were cross-checked by other matching PS1 decomps.)

## Instruction order (sched, reorg)
- Scheduling stays inside a basic block. Order that differs only inside one block is a scheduling question;
  order across a branch or label is a source question (statement order, condition form).
- Equal-priority instructions keep source order. Copying the target block's order back into the statements is the
  fastest fix; equal-priority stores can come out reversed.
- A local assigned exactly once sinks to just before its first use. Making a value its own single-assignment local
  moves it later; assigning it twice (and the second assignment survives) keeps it where it is computed.
- Branch and call delay slots take the nearest eligible instruction above. Loads, `mfhi`/`mflo` and two-instruction
  macros (a global store without gp) are never moved there, so the slot stays `nop`. maspsx puts `nop` in every slot
  the compiler left empty; the assembler doesn't reorder.
- Two branches to the same label usually mean the source condition was the negation (or `||`/`&&` reversed).

## Registers (local-alloc, global, reload)
- Values get registers by density (uses / length of life): a shorter life or more uses wins the earlier register.
  Free registers are taken in number order: `v0 v1 a0-a3 t0-t7 s0-s7`. A value that lives across a call needs `s*`.
- Stack spill slots follow declaration order: reorder the declarations to move them, not the statements.
- In small blocks (3 locals or fewer) registers follow creation order: declare/assign in the target's order.
- Across basic blocks nothing merges two variables: when the target uses one register in both blocks, use one C
  variable.
- A constant or symbol address assigned once is recomputed at each use (no register kept). `&local` is not: it gets a
  register or slot. Pass a stack buffer as an array (`buf`, not `&buf[0]` cached in a pointer) to get `addiu a0,sp,K`
  at every call.
- `register T x asm("$N")` pins are a last resort: they shift every reload to the next register, cascade, and are
  ignored when the value crosses a call on a caller-saved register. Pin one value at a time and re-check.
- An empty asm `__asm__("" : "=r"(x) : "0"(x));` between two uses keeps a value alive in a saved register (stops CSE
  from merging or recomputing it). Output-only `__asm__ volatile("" : "=r"(p));` after a call makes the compiler
  rebuild an address instead of keeping it in `s*`. These cost no bytes; keep them only if they buy the match.

## Loops (loop.c)
- Loop counters may be strength-reduced into pointers; `i < N` can become a pointer compare. Pointer compares give
  `sltu`, int compares `slt`.
- A count-down loop ending in `bgez` comes from an up-counting `for (i = 0; ...)` whose counter is only counted,
  with no call and one store; hand-writing a down-counter rarely reproduces it.
- With a call inside the loop, most memory loads are not hoisted out; without one, invariants are hoisted. An
  invariant used once inside a loop with a call stays inside (`la` in the loop).
- `do { } while ()` with the bound repeated in the guard often matches loops whose test is at the bottom.

## Memory and expressions (cse, expr)
- A store through a plain pointer (`*p = x`) makes the compiler forget all loaded memory; a store to a struct field
  (`p->f = x`) only forgets other struct accesses. This decides whether a later load is reused or repeated, and
  whether loads move above stores: try writing the access as a struct field vs a cast pointer.
- Locals are laid out in declaration order; arrays and structs are 8-byte aligned. A leaf's first local is `sp+0`.
- Load width follows the source type, not the destination: `lh` vs `lhu` vs `lw` tells the field's type.
- A short/char parameter or return costs a `sll`/`sra` (or `andi`) pair at the boundary: declare it `int` if the
  target has no such pair, and the narrow type if it does.
- `-x` stored to a halfword is computed in halfword mode (gives `lhu`). An `int` with a `(u16)` cast can drop an `andi`.
- Whether a constant is built with `addiu` or `li`/`ori` follows the signedness of the stored-to type.
- A struct copy is 4 instructions per word when byte-aligned, 2 when word-aligned: the type's alignment shows.

## switch
- Cases are emitted in source order; an empty case still owns a jump-table slot. A 2-case switch has no lower bound
  check. Stacked labels on one body merge: give each case its own body if the target repeats code.
- Jump tables in the original live in `.rodata` next to the function's other constants: when one moves, see the
  project's notes on jump tables (`jtbl_`) before changing the C.

## Calls
- A move in a `jal` delay slot is the last argument being set: a different one means the argument count or order
  is wrong, not scheduling.
- The value used in a `jal` delay slot was computed before the call: it can't be that call's return value.
- A trailing `jr ra` with `addiu sp` in its slot is the assembler filling the slot, not a different frame.
